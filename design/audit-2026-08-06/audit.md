# Dial UI 审计（2026-08-06）

## 结论

当前界面已经有稳定的视觉语言和完整的数据能力，但首页的信息优先级仍围绕“累计使用量”，没有优先回答用户最紧迫的两个问题：**还剩多少**、**按当前速度还能用多久**。Codex 与 ChatGPT 共用同一套信息模板，也让不同来源的数据含义显得过于相似。

## 做得好的地方

- 数据源切换、刷新、设置入口的位置稳定，核心操作容易找到。
- 大数字、卡片和图表建立了清楚的基础层级，浅色主题整体克制。
- “仅本地日志”“费用为估算”等信息已经存在，为建立可信的数据口径打下了基础。
- 设置项按通用、外观、图表、更新分组，功能覆盖完整。
- 图表柱形已有可访问名称，说明现有实现具备继续完善无障碍体验的基础。

## 关键问题

1. **剩余额度被放在次要位置。** 当前首屏最醒目的是 30 天 token 和费用，而剩余比例在侧栏或折叠区；这与用户查看用量工具时最常见的决策任务不匹配。
2. **官方限额与本地统计边界不够强。** “本地日志估算”只是弱提示，大数字和费用仍可能被误读成 OpenAI 官方账单或官方余额。
3. **Codex 与 ChatGPT 被套入同一模板。** 两者可获得的数据、时间窗口和活跃度含义不同，空槽位与相同卡片结构会制造虚假的可比性。
4. **首屏指标竞争。** 多个同等重量的卡片、大数字和统计行同时争夺注意力，用户需要扫描后才能判断哪一个最重要。
5. **图表占据大量空间但解释不足。** 缺少清晰的纵轴、时间上下文、峰值解释与稀疏数据状态；在 ChatGPT 数据少时尤其显空。
6. **数据源与产品关系不清楚。** 侧栏把 Codex、ChatGPT、Claude、Gemini、OpenCode 并列为独立来源，却没有表达“OpenAI 账户 / 产品 / 本地客户端”的层级。
7. **设置导航与内容结构重复。** 左侧设置导航存在，但多个设置分区仍在同一长页中展示，当前所在分区和跳转反馈不够明确。

## 无障碍风险

- 次级文字、网格线、浅色柱和禁用态对比度偏低，需要以 WCAG AA 为目标实测。
- 主题色选择主要依赖颜色识别，应增加明确的选中标记和文字状态。
- 截图中看不到键盘焦点样式，需要验证侧栏、图表、选择器和切换开关的完整键盘路径。
- 图表虽然有可访问名称，但仍需要可聚焦的数据点、摘要文本或表格替代视图。

## 建议的任务顺序

1. 把“剩余额度 / 重置时间 / 消耗速度”提升为首页主任务，并明确数据来源。
2. 将官方限额、本地日志统计、费用估算分成不同语义层，不再用同一种大数字卡片表达。
3. 为 Codex、ChatGPT 设计共享骨架下的差异化模块，而不是强行填满相同槽位。
4. 重做趋势区：补充时间范围、坐标、峰值说明和稀疏数据空状态。
5. 精简首页指标，并把工作区、模型、会话等诊断信息下沉到可展开区域。
6. 将设置改成真正的分区导航，并补齐对比度、焦点和非颜色选中状态。
